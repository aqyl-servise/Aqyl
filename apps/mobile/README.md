# Aqyl для Android

Обёртка Capacitor: приложение открывает прод-сайт `https://aqyl-service.kz`.
Правки на сайте видны в приложении сразу, без нового релиза в Play.

## Как собирается

**В облаке, через GitHub Actions** — workflow `.github/workflows/android.yml`.
На рабочем компьютере ничего ставить не нужно: сборка идёт на машинах GitHub
с JDK 21 и Android SDK, каждая привязана к коммиту и повторяема.

Запускается автоматически при изменениях в `apps/mobile/**` и вручную —
GitHub → Actions → Android → **Run workflow**, там же указывается версия
для магазина (например `1.0.1`).

Результат — в артефактах запуска (Actions → нужный запуск → Artifacts):

| Артефакт | Что это | Куда |
|---|---|---|
| `aqyl-aab-N` | пакет для Google Play | загружать в Play Console |
| `aqyl-apk-N` | обычная установка | проверить на своём телефоне до публикации |

`N` — номер запуска, он же `versionCode`: Play не принимает повторный, и
берётся он из CI, а не руками.

Пока не заданы секреты подписи, собирается **неподписанный** пакет — для
проверки годится, в Play не примут.

## Ключ подписи (один раз, руками)

Ключом подписывается каждый релиз. **Потерять его нельзя**: без него в Play
не выйдет ни одного обновления, только новое приложение с нуля. Создаёт и
хранит его владелец, в переписку и в репозиторий он не попадает.

Годится любая Java, даже 8 — формат хранилища тот же:

```bash
keytool -genkeypair -v -keystore aqyl-release.keystore -alias aqyl -keyalg RSA -keysize 2048 -validity 10000
```

Спросит пароль хранилища, пароль ключа и данные организации — ТОО «Ақыл
Корп.». Файл `aqyl-release.keystore` и оба пароля сохранить в надёжном месте
(менеджер паролей + резервная копия файла вне компьютера).

Затем в GitHub → Settings → Secrets and variables → Actions добавить четыре
секрета:

| Секрет | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | файл в base64: `base64 -w0 aqyl-release.keystore` (PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("aqyl-release.keystore"))`) |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища |
| `ANDROID_KEY_ALIAS` | `aqyl` |
| `ANDROID_KEY_PASSWORD` | пароль ключа |

После этого сборка подписывает пакет сама. Ключ разворачивается только на
время сборки и в журналы не попадает.

## Правило, которое нельзя нарушать

`appendUserAgent: 'AqylApp/Android'` в `capacitor.config.ts` — не косметика.
По этому маркеру `apps/web/lib/platform.ts` прячет в приложении всё, что
предлагает оплату: Google Play требует продавать цифровые товары через Play
Billing (комиссия 15–30%), а наши пакеты оплачиваются через Kaspi. Уберёте
маркер — приложение получит отказ на ревью.

Что при этом видит учитель в приложении: баланс уроков и сообщение
«Уроки закончились» без цен, кнопок и ссылок на покупку.

## Иконки

Знак приложения рисуется скриптом из фирменного знака (см. историю коммитов)
во все плотности `mipmap-*` и в `store/icon-512.png` — это иконка для
витрины Play, в сам пакет она не входит.

## Публикация в Google Play — что нужно

- Аккаунт разработчика **на организацию** (ТОО «Ақыл Корп.»). Личные
  аккаунты с ноября 2023 обязаны перед публикацией провести закрытое
  тестирование: 12 тестировщиков, 14 дней подряд. Организации от этого
  освобождены.
- **D-U-N-S номер** компании — бесплатный, выдаётся до 30 дней. Это самый
  долгий пункт, подавать первым.
- Политика конфиденциальности: `https://aqyl-service.kz/privacy` — есть.
- Удаление аккаунта: `https://aqyl-service.kz/delete-account` — есть; Google
  требует и ссылку, и возможность удалиться из самого приложения.
- Иконка 512×512 — `store/icon-512.png`, готова.
- Скриншоты телефона (минимум 2), описание на русском и казахском, форма
  Data Safety, анкета возрастного рейтинга.

## Локальная сборка (не обязательна)

Если всё же нужна на своём компьютере: JDK 21, Android SDK (платформа 35),
`ANDROID_HOME`. Затем `npm install`, `npx cap sync android`,
`cd android && gradlew.bat bundleRelease`. На этом компьютере места под SDK
нет — поэтому и собираем в облаке.
